Keyboard & screen reader bench

Park the mouse. Every exercise here is operable with Tab, arrows, Enter, Space and Esc, and each names the ARIA it demonstrates. Reach for native HTML first — ARIA patches what native elements cannot express.

Bench switcher

Test: Tab once to land on the bench list in the sidebar, then move with ↑ ↓ Home End. ARIA: tablist with aria-orientation="vertical", tab, tabpanel, aria-selected, aria-controls, roving tabindex — the whole list is one Tab stop.

Disclosure widget

Test: Enter or Space on a question. ARIA: aria-expanded, aria-controls.

The on-screen marker that shows which element holds keyboard focus (SC 2.4.7).
Native buttons and links ship focus, keys and roles for free; ARIA only fills the gaps (SC 2.1.1, 4.1.2).

Modal dialog

Test: Open it, press Tab (focus stays inside), press Esc (focus returns to the launcher). ARIA: the native dialog plus showModal() supplies the modal role, the focus trap and Esc; aria-labelledby and aria-describedby name it.

Key press journal

Logs each key and the focused element so you can verify focus order (SC 2.4.3). It also tames the deliberate keyboard trap used by the regression sample on bench 02.

      04

      Audit ledger

      Score each success criterion, attach evidence notes, then assemble, copy or print the report.

      Test protocol

      Keyboard alone: Tab, Shift+Tab, Enter, Space, arrows, Esc. Screen readers: NVDA on Firefox or Chrome, VoiceOver on Safari, TalkBack on Android. Magnify to 200%, run the contrast bench, and finish with automated scanners (axe DevTools, Lighthouse, WAVE) — automation catches only a slice of WCAG, so manual passes are mandatory.

      Press “Build report” to assemble your audit summary.

      IncluForge is a teaching bench — it cannot replace testing with real assistive technology, and it only verifies what a browser can compute.
